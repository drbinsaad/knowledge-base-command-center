## Report a reproducible bug

Use the repository's **Bug report** form. A useful report includes:

- plugin version;
- Obsidian version and operating system/device;
- Community Plugins, BRAT, or manual installation;
- Generic or ENT profile and the affected Index/Library/workflow;
- whether several knowledge bases or synced devices are involved;
- minimal reproduction steps in a scratch vault where practical;
- expected and actual behavior; and
- a sanitized console error or screenshot.

Never attach a real <code>data.json</code>, recovery/conflict-rescue JSON, private note body, patient information, credentials, local absolute paths, or copyrighted source text. Replace note titles and paths with synthetic examples.

## Suggest a feature

Use the **Feature request** form. Describe the user problem and desired outcome before proposing implementation. Include mobile, Sync, migration, privacy, and compatibility implications when relevant.

Substantial behavior or data-model changes should be discussed before a pull request is opened.

## Security

Do not disclose a vulnerability or private vault data in a public issue. Follow [SECURITY.md](SECURITY.md), which explains the currently available private-reporting route and what to do when GitHub private vulnerability reporting is not enabled.

## Clinical boundary

The optional ENT preset is an organizational study workflow. Repository support does not provide medical advice, patient-specific guidance, prescribing guidance, or clinical approval. Do not include patient information in any project channel.
