## Supplemental Mac Obsidian evidence

The built 0.19.0 candidate was installed into a synthetic disposable vault and exercised inside real Obsidian 1.13.7 on macOS. Obsidian mobile emulation and Chrome DevTools Protocol viewport/touch emulation were used. This was Obsidian's Electron desktop runtime, not an iPhone or iOS WebKit.

- At a 400 × 1267 portrait viewport with a coarse pointer and five emulated touch points, a custom **Harness Library** heading and nested subheading exposed **Create note here…**. Its form showed the fixed `Harness Library / Create here heading / Create here target` classification, created one synthetic Markdown note, placed it under that nested subheading, and expanded the branch so the new row was visible.
- On the created note, the saved-page Return action appeared directly beside the organization indicator. Both active editor-header actions measured 44 × 44 CSS pixels, and the Return action had the label **Open this note’s saved Knowledge Base Command Center page**.
- After a plugin lifecycle reload, the route remained available through Obsidian's App-local storage, the action remained a saved-page action, and activating it restored the **Harness Library** page and its nested records. Automated tests separately cover full restart reconstruction; the Mac run did not restart the entire Obsidian application because other user vault windows were open.
- An unrelated synthetic note with no saved origin exposed the 44 × 44 **Open Knowledge Base Command Center home** action. Activating it opened a clean Home with **Knowledge Index** selected rather than borrowing another note's route.
- At a 1267 × 400 landscape viewport, the custom Library layout rendered and the created note retained adjacent 44 × 44 Return and organization controls. Sanitized synthetic-vault screenshots were inspected at both viewports.
- Obsidian reported no captured runtime errors and no error-level console messages. The synthetic creation intentionally changed only the disposable vault; no private/user vault was clicked or modified.

These observations support the desktop-emulated responsive layout and plugin lifecycle only. They do not establish physical touch behavior, iOS WebKit behavior, complete application restart behavior on iPhone, Dynamic Type, VoiceOver, Arabic iOS direction, software-keyboard or safe-area behavior, Sync handoff, interruption recovery, or a physical-device Pass.
