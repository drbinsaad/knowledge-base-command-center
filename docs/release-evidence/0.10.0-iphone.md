# Version 0.10.0 physical-iPhone evidence

**Status: partial evidence; the full manual release gate did not pass.**

This note records what is available for version 0.10.0 without turning a screenshot or a limited observation into a broader test claim.

## Available evidence

- [A real, sanitized iPhone portrait screenshot](../assets/search-mobile.png) exists for the released 0.10.0 interface.
- The capture visibly shows the software keyboard open, the query <code>lary</code>, a live result count, search results above the keyboard, compact single-row records, No note badges, and row action menus.
- [PR #16](https://github.com/drbinsaad/knowledge-base-command-center/pull/16) records that the owner physically checked the original blocking portrait-search regression before release.

This supports only the recorded portrait search and compact-row observation. It does not establish general mobile correctness or complete the [manual real-iPhone release checklist](../manual-iphone-release-checklist.md).

## Explicitly unverified for 0.10.0

The owner previously chose to release without completing the remaining physical-iPhone matrix. These areas therefore remain unverified on a physical device for 0.10.0:

- landscape layout, including widths above the former phone breakpoint;
- broad-query 300-row search capping and browse paging;
- destructive fresh-device and delayed-<code>data.json</code> recovery;
- the complete touch import/export and recovery matrix;
- the complete Dynamic Type and accessibility-control pass; and
- the remaining checklist interactions not represented by the portrait screenshot.

Automated DOM and release checks are valuable regression coverage but are not substitutes for those physical-device observations.

## Release interpretation

- Do not describe version 0.10.0 as having passed the full physical-iPhone checklist.
- Do not use the screenshot as evidence for iPad, Android, landscape, accessibility, performance, Sync recovery, or import/export behavior.
- The unverified items are accepted release risk, not known passing results and not necessarily known defects.

## Recommended next gate

Before a future release that changes search, navigation, modals, import/export, Sync handling, or mobile styles:

1. complete every applicable item in the manual checklist on a physical iPhone;
2. record device, iOS, Obsidian, orientation, viewport, Dynamic Type, and result;
3. link sanitized evidence from the release pull request; and
4. leave any skipped item explicitly unverified rather than marking the gate complete.
